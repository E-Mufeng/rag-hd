# 踩坑记录与工程决策（case_study）

> 本文件整理火电运维 RAG 试点过程中遇到的关键坑点与对应决策。所有内容均为**框架演示性复盘**，数据均为模拟，不涉真实业务。

## 1. OCR 表格错乱（离线入湖）

**现象**：扫描版规程 PDF 经 OCR 后，跨页表、合并单元格、竖排表头经常被识别错乱：表头与数据错位、行被截断，导致「主蒸汽温度限额」被错误拼接到相邻设备行，入库后检索命中即答错。

**根因**：通用 OCR 只做字符级识别，不还原表结构；版面分析未区分「正文 / 表格 / 页眉页脚」，表格被当正文切。

**决策与落地**：
- 在 `layout_analyzer.py` 定义 `LayoutAnalyzer` 抽象，版面分析层先区分区块类型；
- `table_parser.py` 把表格**独立成块**并附加 `page` / `table_no` 元数据，检索命中可直接溯源到「表5-2」；
- 真实部署对接内网 PP-Structure / 商业 OCR 的表格还原能力（抽象接口不变）。
- 切片阶段对表格块单独处理，避免与正文混切导致行列错位。

## 2. BGE-M3 稀疏向量踩坑（检索两路调整）

**现象**：早期方案用 BGE-M3 的「稠密 + 稀疏(lexical_weights)」双向量，期望稠密捕语义、稀疏补关键词。但火电术语中英混杂、设备代号固定（如 `F123`、`#1机组`），稀疏权重对这类**定长 token** 的命中不稳定，且稀疏向量需额外存储与索引，付出的运维成本换不回相应收益。

**决策与落地**：
- 砍掉稀疏默认融合，改为**两路 = dense(HNSW) + BM25**（见 `retrieve.py`）。BM25 对设备代号、故障码等定长关键词命中稳定且零模型依赖；dense 补语义。
- dense 索引固定用 **HNSW**（ANN 检索快、资源可控），契合单机试点。
- 粗排保持**宽召回**（`recall_priority: true`），宁多召不漏召关键规程片段，精排阶段再靠 rerank 收敛。

## 3. 意图识别边界 case（C2 双闸门 + _DOMAIN_HINTS）

**现象**：
- 闲聊「你好你是谁」被误判可答；领域外「今天股票行情」一度进入检索白白消耗资源。
- 边缘 case：用户问「锅炉和汽机的区别」属领域内需答，但「锅炉牌子的评价」属领域外——纯关键词容易误判。

**决策与落地**：
- 引入 `_DOMAIN_HINTS` **全局前置守卫**（`intent.py`）：先用强领域信号词（锅炉/汽轮机/限值/跳闸…）与领域外词（股票/菜谱…）做**零成本预筛**，领域外直接前置拒答，省检索。
- **双闸门相互独立**：前置闸门（意图置信度 < `intent.threshold` 不检索）+ 检索后置信度闸门（`rerank.py` 二次把关），两层互不替代。
- MiniLM 为主 + **规则兜底**：模型服务不可用时退回关键词规则，保证可用性。
- 拒答 / 低置信请求**日志落盘**（`log_reject` / `log_low_conf`），供维护班回流优化 `_DOMAIN_HINTS` 与术语库。

## 4. Rerank 假阳性风险（C4）

**现象**：Cross-Encoder 对「表述相似但事实相反」的片段容易高分（如把「超温需降负荷」与「超温可升负荷」判为相关），造成精排假阳性，进而高置信答错。

**决策与落地**：
- 精排仅做**排序收敛**，**不直接等价于事实正确**；置信度聚合仍结合 Top-3 整体分布（`aggregate_confidence` 的 Top-3 加权，而非单点）。
- `generate.py` 的 Prompt 模板强制**幻觉抑制 + 来源可回溯**：要求答案标注引用章节/页码，事实性错误可被溯源复核。
- 低置信（0.4~0.7）走「给答案 + 明确提示资料置信度有限，请核实」，把不确定性显式交还给用户，而非假装确定。

## 5. 置信度阈值怎么定（D1）

**现象**：阈值定太高 → 大量本应答的被拒（漏答，维护班不满）；定太低 → 答非所问、幻觉漏出。

**决策与落地**（最终采用）：
- **≥0.7 直接答**（高置信，附溯源）；**0.4~0.7 medium**（给答案 + 低置信提示，建议核实）；**<0.4 拒答**。
- 聚合策略用 **Top-3 加权 + Top1 高分兜底**（`top1_fallback: 0.92`）：对「明确参数限额查询」这类强单点命中，Top1 极高时直接采用，避免被后续低分拉低而误拒。
- **阈值与后端强相关**：BGE cross-encoder 的输出是校准分，与 BM25 的饱和分量纲不同，换检索或精排后端后必须重新标定，不能照搬。
- 标定方式：抽现场问答样本交维护班复核，看「误拒」与「误答」的权衡后再定稿，而非拍脑袋。阈值统一写在 `configs/base.yaml` 的 `confidence` 段，改配置即可生效、无需改代码。
- 线上持续观察：低置信与拒答请求落盘（`data/logs/`），后续据此补充术语表与领域提示词。

## 6. 小结

- 架构上**业务与基础设施解耦**：所有外部依赖走抽象接口 + mock，配置切换 mock / 真实后端。
- 质量上**双闸门 + 置信度分级 + 溯源 + 落盘回流**，把不确定性显式管理，而非掩盖。
- 工程上**可演进**：试点用单机容器对齐生产，规模上涨仅改配置升集群，业务代码不动。
